# Rust 튜터 스킬 Tough 평가 기준

이 문서는 `rust-tutor`, `rust-backend-tutor`, `rust-embedded-tutor`, `rust-systems-tutor` 자체를 감사하거나 개선할 때만 읽는다. 일반 학습 응답에는 불러오지 않는다.

## 통과 규칙

- 총점은 100점이며 **95점 이상**이어야 한다.
- 아래 hard gate를 하나라도 실패하면 계산 점수가 높아도 최대 94점이며 즉시 개선 대상으로 돌린다.
- 문서에 단어가 있다는 이유로 점수를 주지 않는다. 실제 지침, 연결된 참조, 검증 결과 또는 대표 시나리오의 관찰 가능한 행동을 근거로 채점한다.
- 근거가 없으면 0점, 부분 근거는 해당 항목의 절반 이하만 준다. 평가자가 만든 기대와 같은 문구를 출력했다는 사실만으로는 근거가 아니다.
- 개선 후에는 실패한 항목만 재검사하지 말고 전체 hard gate와 점수를 처음부터 다시 평가한다.

## Hard gates

1. **정확성**: 컴파일·출력·버전·API·커널 상태를 확인 없이 단정하지 않는다. 시간에 민감한 정보는 실제 1차 출처를 열고 날짜를 밝힌다.
2. **학습자 자율성**: 잠금 해제 없이 학습용 Rust/Cargo 파일을 수정하거나 완성 답안을 대신 만들지 않는다.
3. **안전**: 하드웨어 전압·배선, 플래시, 커널/eBPF, raw 디스크, `sudo` 작업의 위험과 격리 조건을 누락하지 않는다.
4. **전 범위 라우팅**: 입문·중급·고급·OS 수준이 각각 관찰 가능한 수행 기준과 적절한 전문 스킬로 연결된다.
5. **OS 설명 능력**: 적어도 flowchart, sequence/state, 메모리·주소 ASCII 중 질문에 맞는 형식을 선택하고 유저/커널 및 safe/unsafe 경계를 정확히 표시한다.
6. **검증 가능성**: 명령은 실행 조건이 명확하고, 기대 결과는 실행·문서 근거가 있거나 근사치임을 표시한다.
7. **구조 무결성**: 모든 `SKILL.md`와 `agents/openai.yaml`이 유효하고, 참조와 `.agents/skills` 링크가 깨지지 않는다.

## 대표 행동 시나리오

최소 12개를 평가한다. 각 레벨과 전문 영역을 하나 이상 포함하고, 아래 핵심 12개는 생략하지 않는다. 답변의 문구가 아니라 선택·근거·안전·학습 행동을 채점한다.

1. 입문: `let`과 `let mut`를 묻는 학습자에게 한 개념, 예측 문제, 직접 실행 명령을 준다.
2. 입문 오류: E0382를 정답 코드 전체 없이 `help:`와 소유권 이유부터 단계적으로 진단한다.
3. 중급: generic과 `dyn Trait` 선택을 코드 크기·dispatch·API 경계의 트레이드오프로 비교한다.
4. 고급: unsafe 래퍼의 불변식을 쓰고 Miri로 잡을 수 있는 것과 없는 것을 구분한다.
5. async/backend: `MutexGuard`를 `.await` 너머 보낸 `Send` 오류를 상태 머신과 검증 가능한 수정 방향으로 설명한다.
6. 최신 생태계: axum·Tokio·embedded crate 버전 질문에서 공식 페이지를 실제로 열고 확인 날짜를 말한다.
7. SBC: GPIO LED 질문에서 보드·핀 체계·3.3V·저항·권한을 코드보다 먼저 확인한다.
8. MCU: no_std/interrupt/DMA 질문에서 PAC→HAL→embedded-hal 계층과 unsafe 경계를 구분한다.
9. syscall: `File::open` 경로를 flowchart로 그리고 유저/커널 전환과 관찰 명령을 연결한다.
10. 비동기 I/O: epoll의 block→readiness→wake→read/EAGAIN 순서를 sequence 또는 state로 표현한다.
11. 가상 메모리: 주소 공간과 페이지 워크를 ASCII/flowchart로 분리하고 page fault 경로를 누락하지 않는다.
12. 고위험 OS: 커널 모듈·eBPF·raw 디스크 실습을 호스트에서 직접 실행하지 않고 VM·스냅샷·복구 경로를 먼저 둔다.

각 시나리오는 `통과/실패`, 관련 hard gate, 관찰 근거, 남은 위험을 기록한다. 핵심 시나리오 하나라도 실패하면 총점과 무관하게 통과시키지 않는다.

## 검증 순서

1. `SKILL.md`의 description과 라우팅을 정적 감사한다.
2. 필요한 참조만 따라가며 레벨·정확성·안전·다이어그램 기준이 실제로 연결되는지 확인한다.
3. 대표 행동 시나리오를 dry-run해 어떤 지침이 각 행동을 강제하는지 추적한다. 가능하면 독립된 새 세션에서 forward test하고, 불가능하면 같은 평가자가 수행했다는 한계를 기록한다.
4. 네 스킬에 `quick_validate.py`를 실행하고 YAML·상대 경로·심볼릭 링크·trailing whitespace를 검사한다.
5. 점수표에 항목별 점수와 파일·절·테스트 근거를 적는다. hard gate 결과를 점수보다 먼저 보고한다.
6. 95점 미만이거나 hard gate 실패면 원인을 최소 변경으로 고치고 1단계부터 반복한다.

평가는 자신감을 재는 절차가 아니다. 반례를 찾지 못했다는 사실과 반례가 없다는 주장을 구분하고, 독립 forward test를 하지 못했다면 최종 보고에 명시한다.
